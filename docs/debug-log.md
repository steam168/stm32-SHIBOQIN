## A. 起步总纲（三条"保命"认知）

**0-1. 外设时钟不使能，一切免谈**
所有用到的外设、GPIO 务必先开时钟（RCC 使能），否则后续所有配置都是无效操作。
> 排查任何"外设没反应"问题，第一步先查时钟树，不要先怀疑代码逻辑。

**0-2. 函数内数组活不过函数返回**
在函数内定义的数组位于栈上，函数结束即释放，其他函数拿不到数据。
多个函数要访问的数据，用全局变量或 `static`。
> 这条直接导致了后来的第 23 条（栈溢出）事故。

**0-3. 定时器三种模式，别混用结构体**
时基单元 / 输入捕获 / 输出比较是三种模式，各有独立的结构体要分别定义。
输出比较模式下：`CCR` 只改 PWM 占空比；`ARR` / `PSC` 都会改变频率。
采样率公式：`f = 72MHz / [(ARR+1)(PSC+1)]`，ARR 与 PSC 都要花时间调整。

## B. ADC / DMA / SPI 外设配置

**1. ADC 配置四件套**
初始化结构体之后：选通道 → 校准 → 选模式（连续 / 扫描 / 单次）→ 数据对齐。
少任何一步转换都不会正常出数。

**2. DMA 配置要素**
- 寄存器地址与外设地址都要填（ADC 扫描模式才会用到外设地址）
- 内存地址、内存自增（数据从外设搬到内存的依据）
- ⚠ 位宽陷阱：SPI 的数据寄存器只有 8 位，但 TFT 屏幕需要 16 位数据才能表示颜色。
  必须把 `uint16_t` 拆成两个字节发送，否则高 8 位被舍弃，只剩低 8 位，颜色全错。
- ⚠ DMA 传输长度寄存器是 16 位，最大 65535。以 TFT 全屏为例
  128×160×2 = 40960 字节，接近上限，更长数据必须分块。

**3. SPI 的 DMA 有个隐藏前提**
SPI 速度很快（最大 36MHz），但**只有在双向（全双工）模式下 DMA 才正常工作**，
单向模式下 DMA 无反应。→ 这就是早期"DMA 不启动"故障的根因。

**4. InitTypeDef 结构体不能反复 Init**
`InitTypeDef → InitStructure` 反复调用，会给没有明确赋值的成员填默认值，
最终导致 DMA 初始化异常 / 配置异常。
**正确做法**：声明一次结构体，之后只修改需要的成员，不再重复调用 Init 函数。

**5. 外设 / DMA 排查 checklist**
外设使能了吗？DMA 通道使能对了吗？外设的 DMA 地址写对了吗（如 `ADC→DR`）？
DMA 传输模式匹配吗？

**6. DMA_DeInit 会误删关联**
错误调用 `DMA_DeInit` 会先清降原本已开启的 SPI-DMA 关联与触发，
相关外设寄存器的值也被清掉。**这个函数要少用。**

**7. 重新初始化外设同样会解除关联**
重新初始化某个外设（如 `DMA_Init`）也会把关联解除。
所以初始化尽量只做一次，运行时的参数调整只改必要的寄存器。

**8. 关联外设放在一起初始化**
逻辑清楚，不容易忘。

## C. 中断与共享变量

**9. 中断标志位：清零与查询是两回事**
中断标志位要用**清零**（清除 IT 的宏）才能正确退出中断；
只有查询类场景才能用 `FLAG` 普通标志位。混用会重复进中断或卡死。

**10. NVIC 分组与中断纪律**
- NVIC 中断分组设置放在 `main` 最前面
- 收发等待不要用 `while` 死等，用状态标志位判断
- 中断函数必须确认是从哪里进入的（多个中断共用一个 ISR 时要判断）
- 中断里不能干太耗时的任务，尽量轻量化
- 退出前必须清除中断标志位

**11. 共享变量必须加 volatile**
中断与主循环共享的变量，必须用 `volatile` 告诉编译器"这个变量随时被硬件修改"。
否则编译器优化后：写内存时不回写、读内存时不再访问内存（直接用寄存器里的旧值），
主循环可能永远看不到中断改的新值。**后果严重。**

**12. 按键不要 while 忙等**
轮询式按键检测用 `while` 等待松手，遇到短路 / 异常会使程序卡死。
改硬件中断（EXTI）在中断里检测。

**13. 忙等待要加超时**
"先等待、后中断"结构的 `while`，如果中断始终不来就永久卡死。
所有忙等待必须加超时兜底。

## D. C 语言与数据类型

**14. 强制类型转换要放在除法之前**
`(uint16_t)Arrdy[2]/4095*3.3` 是整数除法先截断，小于 1 直接变 0。
正确：先转 `float` 再除 —— `(float)Arrdy[2]/4095.0*3.3f`。

**15. 裸机 float 运算要加 f 后缀**
单片机没有硬件浮点，`float` 运算全加 `f`（如 `3.3f`），否则按 double 算，慢且占栈。

**16. uint8_t 数学溢出**
`uint8_t` 最大 255，循环变量/中间计算很容易静默溢出。
循环变量用 `uint16_t`，确定范围在 255 内才用 `uint8_t`。

**17. 数组越界——最严重的一类 bug**
数组越界非常危险：程序卡死、数据错乱，而且现象离根因很远。
所有数组必须严格确定边界，边界条件要反复确认（见 22）。

**18. 栈溢出：大数组不许进函数**
函数内定义的大数组会被压入栈中，函数返回时释放。
**DMA 传输失败的真正原因就是它**：数组随栈释放，DMA 还在往已释放的栈空间里写。
在函数内定义过大的数组会栈溢出。
→ 大数组加 `static` 提升为全局变量。

**19. 串口 Tx / Rx 接线与逻辑**
收发双方的逻辑要对齐（谁发起、谁应答、电平域）。

## E. 实践迭代记录（架构是这么演进出来的）

| # | 尝试 | 结果 |
|---|---|---|
| 5 | TFT 画点 / 画线 / 画波形（软件逐点） | ❌ 刷新速度太慢，只够简单画线 |
| 6 | 改用 DMA 硬件把数据经 SPI 发给屏幕 | ✅ 帧率大幅提升、省 CPU；但有 `while` 等 DMA 完成，待并行化 |
| 7 | 帧缓冲方案（整屏显存） | ⚠ 可行但 20KB SRAM 装不下 40KB，占用过大，不推荐 |
| 8 | 帧缓冲优化为"无帧缓冲模式"：逐行生成、行内存储、实时刷新 | ✅ 占用小；但存在屏幕撕裂，改为按块区域发送缓解 |
| 9 | 加入滤波算法：滑动窗口中值平均 | ✅ 去掉最大最小后取中间值赋给窗口中点，噪声明显改善 |
| 10 | DMA 发送合并：不再每行发一次，把 8 行数据一次交给 DMA 再发 SPI | ✅ 大量节省时间，帧率显著提升 |
| 11 | 加入状态机：旋钮 / 按钮控制各项功能（"伪系统"） | ✅ 操作体验质变 |
| 12 | 冻结模式：按一下暂停刷新，屏幕定格 | ✅ |
| 13 | 上位机：VOFA+ 经 USART 绘制，波形保存与回放 | ✅ |

**画波形算法完整演进链**（最值得讲给面试听的一段）：

```
全帧发送（软件画波形）
   └─ RAM 装不下 40KB 全屏数据，且代码多、显示效果差
        └─ 缩小显示范围 + 双缓冲
             └─ 显示效果差
                  └─ 无帧缓冲模式：逐 8 行生成 → DMA 推送 → 双缓冲交替
                       └─ 屏幕可能撕裂 → 每行发送 → 块区域发送
                            └─ 帧率仍卡（每行反复调 DMA 浪费大量时间）
                                 └─ 8 行合并一次交给 DMA（实践 10）
```

**分层架构**（手绘框架整理）：

```
应用算法层   模式状态机 / 滤波 / Vpp 计算 / 触发引擎
   │
交互层       按键 / 旋钮（ADC2 采样）
   │
显示层       TFT（SPI+DMA）/ OLED（I2C）
   │
发送层       串口 DMA（上位机）
   │
驱动层       ADC / SPI / TIM / GPIO
   │
底层         时钟树 / NVIC
```
